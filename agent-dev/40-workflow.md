# 40 Workflow & Verification

本文件适用于所有会修改仓库的任务，以及验证、审查、提交、发布准备和失败恢复。

## 1. 开始阶段

1. 按 `AGENT_DEV.md` 完成必读和任务路由。
2. 运行 `git status --short`，确认分支、未提交与未跟踪文件。
3. 阅读 `package.json` scripts、相关实现、测试和文档，不盲改。
4. 明确用户授权边界和验收条件；只诊断时不得实施修复。
5. 识别风险：权限、Key、网页数据、远端请求、存储迁移、成本、依赖、许可证和发布。
6. 复杂任务建立计划；一次最多一个步骤标记为进行中。

## 2. 实现阶段

- 先修改契约或测试，再实现行为；小型文案/机械变更可直接同步更新。
- 每个小步后检查相关 diff，防止改动扩散。
- 保留用户已有变更，不格式化无关文件，不顺手升级依赖。
- 新增错误路径必须给出停止、重试或恢复行为。
- 修改安全/权限/存储/成本/Provider 契约时，同步更新 PRD、架构或相应规范。
- UI 修改同时处理 loading、empty、error、disabled、keyboard 和窄屏状态。

### 2.1 产品演进记录

代码、文档和记录共同构成可审计的产品演进。满足以下条件时必须在同一轮维护对应文件：

| 变化 | 必须更新 |
| --- | --- |
| 阶段范围、优先级、状态或退出条件变化 | `docs/PRODUCT-ROADMAP.md` |
| 一轮用户功能、架构、安全、成本或产品治理增量开始或完成 | `docs/ITERATION-LOG.md` |
| 用户可见功能、行为变化、修复、弃用、移除或安全修复 | `CHANGELOG.md` 的 `Unreleased` |
| 产品需求、非目标或验收标准变化 | `docs/PRD.zh-CN.md` |
| 系统边界、消息、存储、权限或数据流变化 | `docs/ARCHITECTURE.md` |

维护时必须遵守：

- 路线图是计划和状态的事实来源；迭代记录是实际工作和证据的事实来源；CHANGELOG 只面向发布用户，不互相复制全部内容。
- 新迭代采用 `TD-YYYY-NNN`；不得复用编号、伪造历史 commit/tag、发布日期或已发布状态。
- “已验证”必须附实际测试或人工检查证据；“已发布”必须能对应版本号、发布物和 Git tag。
- 延期、取消或移出阶段的项目保留原因与去向，不得从路线图静默删除。
- `docs/ITERATION-LOG.md` 超过 20 个已结束条目时，将较早条目按年份归档到 `docs/iterations/YYYY.md`；主文件必须保留活动条目和归档索引。
- 纯拼写、格式或不改变行为的小型内部修订可以不新增迭代条目，但仍需更新已有条目的验证或文档日期（若适用）。

## 3. 验证矩阵

根据变更选择最小充分集合；不允许用较弱检查替代必需检查。

### 文档或规范变更

```bash
git diff --check
rg -n '旧名称|旧许可证|失效路径' README.md docs AGENT_DEV.md agent-dev .github
```

同时人工检查链接、规则路由、重复/冲突、路线图状态、迭代证据、CHANGELOG 发布状态和决策一致性。

### TypeScript、React、Provider、Storage 或配置变更

```bash
npm run typecheck
npm test
npm run build
git diff --check
```

失败时保留原始错误，定位首个根因。不能只重跑直到偶然通过。

### Manifest、权限或注入逻辑变更

除完整工程检查外，必须检查生成产物：

```bash
sed -n '1,240p' .output/chrome-mv3/manifest.json
rg -n 'content_scripts|<all_urls>|permissions|host_permissions|optional_host_permissions' .output/chrome-mv3/manifest.json
```

确认没有未文档化权限、静态全站脚本或远程代码。

### 安全、密钥或隐私变更

- 为边界行为添加或更新自动化测试。
- 检查 Key 不会进入消息响应、内容脚本、错误或账本。
- 在源码与构建产物中搜索常见秘密和认证头；仅报告命中位置，不打印真实秘密。
- 复核数据字段的目的、位置、生命周期、访问者和清除方式。

### UI 变更

- 完成工程检查。
- 在真实构建扩展中检查 Popup 和 Options；覆盖默认/窄屏/桌面、键盘和状态变化。
- 保存截图只用于本地 QA；含私人页面或 Key 的截图不得进入仓库。
- 无法使用浏览器时明确记录未执行的视觉验证。

### 成本、预算或日期逻辑变更

- 使用固定币种、单价、输入/输出 token 验证公式。
- 覆盖实际/估算、50/80/100 阈值去重、本地跨日、用户覆盖和清理。
- 不调用真实付费模型作为自动化验收。

## 4. 独立复核

实现完成后进行一次新的验证回合，不沿用实现过程中的假设：

1. 从用户验收条件重新逐项核对。
2. 阅读完整 diff，而不只看刚编辑的函数。
3. 检查反例、失败路径和安全边界。
4. 运行验证矩阵并检查生成 Manifest/产物。
5. 再次运行 `git status --short`，确认没有临时文件或无关变更。

默认由当前 Agent 做“新一轮”复核。只有用户明确要求或授权并行 Agent 时才委派独立审查。

## 5. 故障与恢复

- 首次失败：保存完整命令、退出码和首个有意义错误，定位根因。
- 第二次失败：必须改变条件或方法，例如缩小测试、检查环境、修正假设。
- 同一条件第三次前停止盲重试，报告根因、已尝试方案、当前安全状态和所需输入。
- 工具中断后先检查文件和进程是否实际完成，再决定重试，避免重复写入或重复发布。
- 上下文压缩后恢复执行账本、状态与 diff；完成的步骤不重做。
- 若用户在执行中改变目标，判断是替换还是追加，并明确调整计划。

## 6. Git 与外部动作

- 除非用户明确要求，否则不 commit、不 push、不创建 PR、不打 tag、不发布。
- 禁止 `git reset --hard`、强制 checkout、清理整个工作树或覆盖用户修改。
- Commit 必须单一目的，说明权限/隐私影响和验证结果；不伪造作者或签名。
- GitHub 远程仓库已由项目所有者提供；除非用户明确授权，不自行 commit、push、创建或修改远程内容。
- 外部网站自动测试只做公开、无需登录页面，不绕过限制，不保存第三方全文。

## 7. 收口报告

最终报告必须简洁包含：

- **结果**：完成了什么，用户可看到什么变化。
- **关键决策**：安全、产品、权限、许可证或架构选择。
- **验证**：实际运行的命令和结果；浏览器/真实 Provider 验证单独说明。
- **剩余风险**：未执行验证、已知限制和下一步，不隐藏失败。
- **规范变更**：若修改 `AGENT_DEV.md` 或 `agent-dev/`，说明新增/调整的控制点。

不得声称未运行的验证已通过，不得把“编译通过”等同于浏览器行为或视觉验收。

## 8. 规范自检清单

修改 Agent 规范后逐项检查：

- [ ] 自动发现入口仍然只指向 `AGENT_DEV.md`。
- [ ] 必读文件和任务路由完整，执行者无需猜测。
- [ ] 风险动作明确区分可直接执行、先确认和禁止。
- [ ] 上下文压缩、工具失败、用户打断和重试均有恢复路径。
- [ ] 完成标准包含实际验证和最终 diff/status 复核。
- [ ] 安全与运行时硬契约没有被其他层弱化或重复冲突。
- [ ] 新规则可被命令、测试、人工检查或明确证据验证。
- [ ] 临时偏好没有被误写成永久项目政策。
