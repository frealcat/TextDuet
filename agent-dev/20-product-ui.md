# 20 Product & UI Rules

本文件适用于 Popup、Options、网页内状态、文案、样式、可访问性和用户流程变更。

## 1. 产品表达

- 正式名称始终写作 `TextDuet`，仓库与代码标识使用 `textduet`。
- 核心文案：`Your key. Two languages. One page.`；中文价值主张是“自己的 Key、自己的模型、原文译文同页阅读”。
- 不把产品描述为“AI 免费翻译”。应写“无插件订阅费”，并紧邻说明模型 API 可能收费。
- 语气克制、透明、可诊断。不要使用夸张的“无限”“绝对安全”“零成本”“支持所有网站”。
- 优先解释用户结果，再解释 API Base URL、token、Origin 等术语。

## 2. 信息架构

### Popup

Popup 只承担高频控制：

- 当前配置是否可用（脱敏）。
- 目标语言。
- 翻译、停止、打开设置。
- M1 的本次预估、今日用量和预算提醒摘要。
- 当前页面不支持、未配置、翻译中、已停止、部分失败和完成状态。

不要把完整 Provider 表单、价格编辑器或长帮助文案塞入 Popup。

### Options

Options 负责低频配置：

- Provider 预设、自定义 HTTPS Base URL、模型名称和 API Key。
- 会话保存/本机持久保存选择及风险说明。
- 连接测试、Origin 授权、错误诊断。
- M1 的价格、币种、每日预算、阈值和本地账本清理。
- 隐私、数据去向与权限说明。

配置保存和连接测试必须有独立状态，不得用一个含糊的成功提示掩盖其中一个失败。

## 3. 状态与错误

每个异步流程至少覆盖：空闲、进行中、成功、可恢复失败、不可用。错误要给出下一步：

- 401/403：检查 Key、组织或模型权限。
- 402/余额：前往厂商检查余额。
- 404：检查 Base URL、接口协议和模型名。
- 429：说明限流并建议稍后重试。
- 5xx/网络：说明服务或网络状态，显示是否会重试。
- 畸形响应：保留原文，说明模型返回格式不符合要求。
- 权限拒绝：说明需要访问哪个 API Origin，并允许重新触发。

不得向用户显示 Key、完整认证头、完整远端响应或包含正文的调试对象。

## 4. 成本体验

- 翻译前显示输入/输出 token 和成本区间，不展示伪精确单点值。
- 翻译后区分“实际 usage”和“估算”。
- 今日预算提醒同时使用文字、图标或进度，不只靠颜色。
- 50%、80%、100% 的语气分别为提示、警告和达到预算；100% 默认仍由用户决定是否继续。
- 每个价格旁显示币种、每百万 token 单价和更新时间；提醒以厂商账单为准。

## 5. 视觉基线

- 延续当前克制、轻量、阅读工具式视觉，不引入无关的拟物、霓虹、玻璃拟态或装饰性 AI 渐变。
- 使用已有 CSS 变量和绿色品牌强调色；新增 token 先在页面根级统一定义，避免散落魔法色值。
- Popup 的默认目标宽度保持 Chrome 工具栏可用，关键操作无需横向滚动。
- Options 在窄屏和桌面均可阅读；表单标签、帮助、错误与控件保持清晰关联。
- 动效只用于状态反馈，遵守 `prefers-reduced-motion`，不得阻塞操作。

## 6. 可访问性

- 所有输入、选择和按钮都有可访问名称；仅图标按钮必须有 `aria-label`。
- 非提交按钮显式使用 `type="button"`。
- 键盘焦点清晰，Tab 顺序符合视觉顺序；不要只在 hover 时暴露关键操作。
- 正文和控件达到 WCAG AA 对比度目标；错误、预算和连接状态不能只用颜色表达。
- 异步状态使用合适的 `aria-live`，避免频繁播报逐段进度。
- 长错误文本和模型名必须换行或截断并允许查看，不得撑破布局。

## 7. UI 变更验证

UI 任务完成前必须：

1. 运行 typecheck、测试和生产构建。
2. 在构建后的 Chrome 扩展中检查 Popup 与 Options 的主流程。
3. 至少检查 Popup 默认宽度，以及 Options 的窄屏和桌面宽度。
4. 使用键盘完成关键操作，并检查 focus、label、loading、error 和 disabled 状态。
5. 若无法运行真实浏览器验证，明确列出未验证页面与风险，不得声称视觉验收完成。
