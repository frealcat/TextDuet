## 1. 产品摘要

TextDuet 是一款本地优先的双语网页翻译扩展。它不销售翻译套餐，也不代理模型调用。用户自行配置模型服务商的 API Key、API Base URL 和模型名称，扩展直接向该服务商发送翻译请求。

核心价值主张：

> 不再为“使用某个模型的资格”重复支付插件订阅费。用户掌握模型选择、调用成本、提示词和数据去向。

“无插件订阅费”不等于“翻译零成本”。用户仍需承担所选模型服务商产生的 API 费用，产品必须在配置与帮助页面明确说明。

## 2. 设计简报

我们正在为经常阅读外语网页、已经拥有或愿意申请模型 API 的个人用户，设计一个浏览器双语阅读工具。它帮助用户在三分钟内完成模型连接，并在不离开原网页的情况下阅读逐段译文。产品应当显得克制、可信、透明，而不是强调“免费”后隐藏模型成本。当前 Popup 与 Options 采用暖纸色、白色表面、赤陶色主操作和赭石色辅助的阅读工具式主题，保证设置密度与网页阅读场景一致。

用户雇佣这个产品完成的任务是：“让我用自己的模型，在当前网页上稳定地看到与原文对应的译文。”

主要顾虑：

- API Key 是否会被项目方或网页窃取。
- 网页内容会被发送到哪里。
- 为什么模型可以聊天却无法通过连接测试。
- 翻译是否破坏网页布局或消耗失控。

用户第二天应记住：**自己的 Key、自己的模型、文本不经过项目服务器。**

## 3. 问题与机会

现有沉浸式翻译产品通常将高质量 AI 模型、文档翻译或高级规则置于订阅方案中。与此同时，越来越多用户已经直接购买 OpenAI、DeepSeek、OpenRouter、硅基流动等厂商的 API 服务，却仍需向插件再次付费才能使用相似能力。

BYOK 模式可以降低重复付费感并扩大模型选择，但会引入新的门槛：密钥申请、接口地址、模型名称、额度、网络和权限。项目的竞争力不只是“允许填写 API Key”，而是把这些技术概念转化为可理解、可诊断的配置体验。

## 4. 目标与非目标

### 4.1 MVP 目标

1. 新用户在三分钟内完成 OpenAI 兼容模型配置并通过连接测试。
2. 用户点击一次即可翻译当前普通文章网页。
3. 原文与译文逐段对应，停止或刷新后不破坏原网页数据。
4. API Key 仅在扩展可信上下文使用，不进入网页内容脚本。
5. 安装时不要求“读取所有网站”权限，网页与 API 域名按需授权。
6. 错误信息能区分配置、授权、认证、额度、限流、服务端与解析问题。

### 4.2 MVP 非目标

- PDF、EPUB、漫画和图片 OCR。
- YouTube、Netflix 等视频字幕翻译。
- 输入框翻译、划词词典和语音朗读。
- 用户账号、云同步、团队术语库。
- 项目托管的中转 API 或付费套餐。
- Safari 发布。
- Edge、Firefox 和其他浏览器的专项兼容。
- Chrome Web Store 或其他浏览器商店分发；首版仅交付可本地加载的 Chrome 扩展包。
- 对所有复杂 Web App 提供完美布局兼容。

## 5. 目标用户

### P1：技术型跨语种读者

- 阅读英文技术文档、GitHub、论文或行业新闻。
- 已有模型 API Key，理解模型和 token 的基本概念。
- 重视模型自由、成本控制和可审计性。

### P2：愿意跟随引导配置的普通读者

- 知道常见 AI 产品，但不熟悉 API Base URL。
- 因插件订阅价格寻找替代方案。
- 需要服务商预设、示例模型名和清晰错误解释。

MVP 优先服务 P1，同时保证 P2 能通过预设和连接测试完成配置。

## 6. 产品原则

1. **本地优先**：没有必要的数据不离开浏览器；没有必要的服务不经过项目服务器。
2. **最小权限**：权限在用户触发具体功能时申请，并解释用途。
3. **成本透明**：清楚说明插件无订阅费，但模型 API 可能收费。
4. **原文可回退**：翻译层不改写或删除原始文本。
5. **失败可诊断**：不使用含糊的“翻译失败，请重试”作为唯一反馈。
6. **兼容优先于厂商特性**：首版使用广泛兼容的 Chat Completions 协议。
7. **输出不可信**：网页文本和模型返回值都必须经过边界校验并作为纯文本渲染。

## 7. 核心用户流程

### 7.1 首次配置

1. 用户打开扩展设置页。
2. 选择服务商预设或填写自定义 API Base URL。
3. 填写模型名称和 API Key。
4. 选择“仅本次会话”或“持久保存在本机”。
5. 点击“测试连接”。
6. 扩展申请该 API Origin 的网络权限。
7. Service Worker 发出最小测试翻译。
8. 成功后显示具体模型名称；失败时显示可操作的原因。

### 7.2 翻译当前网页

1. 用户打开一个 HTTP/HTTPS 网页。
2. 点击扩展图标，选择目标语言。
3. 点击“翻译当前网页”。
4. 扩展通过 `activeTab` 临时访问当前页面。
5. 内容脚本识别可见文本块并分批发送翻译请求。
6. 译文按段落 ID 插入原文下方。
7. 本次运行继续监听滚动或动态加载后新增的可见正文，并自动增量翻译。
8. 用户可以停止后续批次和新增内容监听，或刷新网页恢复初始状态。

### 7.3 错误恢复

- 未配置 Key：打开设置页并定位至密钥字段。
- API Origin 未授权：重新触发权限申请，不发送请求。
- 401/403：提示检查 Key、组织权限或模型权限。
- 402/余额不足：提示前往模型厂商检查余额。
- 404：提示检查 Base URL、接口协议或模型名称。
- 429：暂停请求，展示限流并允许稍后重试。
- 5xx/网络错误：指数退避后允许继续未完成批次。
- 返回格式错误：保留原文，允许使用更严格提示词重试。

### 7.4 成本预估与每日预算

1. 用户为当前模型填写输入和输出单价，或采用版本内置的价格参考值。
2. 翻译前展示预计输入 token、预计输出 token 和预计成本区间。
3. 翻译后优先使用模型接口返回的 `usage` 数据记录实际 token；没有 `usage` 时记录估算值。
4. 用户可设置本地每日预算与显示币种。
5. 达到 50%、80% 和 100% 时分别在 Popup 与网页状态条提醒。
6. 100% 后默认只提醒；用户可以主动启用“达到预算后暂停新任务”。
7. 用户可选择“本次继续”或“今日继续”，所有覆盖操作只保存在本机。

## 8. 功能需求

### FR-001 模型配置（P0）

- 支持 API Base URL、API Key、当前模型名称，以及同一服务商下多个可切换模型名称/code；多模型通过回车或逗号生成标签，标签可切换当前模型和单独删除。
- 提供阿里云百炼 Qwen、OpenAI、DeepSeek、OpenRouter、硅基流动预设。
- Base URL 仅允许 HTTPS。
- 自动追加 `/chat/completions`；若用户已填写完整路径则不重复追加。
- 模型名称不做静态白名单限制。

验收：用户可填写任意 HTTPS OpenAI 兼容接口并保存。

### FR-002 API Key 生命周期（P0）

- 默认保存方式为 `storage.session`。
- 用户可主动选择 `storage.local` 持久保存。
- 持久保存时显示未加密风险说明。
- Key 不显示明文回填，不写入日志，不进入错误遥测。
- Key 不发送给内容脚本。
- `local` 与 `session` 存储限制为扩展可信上下文。

验收：关闭浏览器后，会话级 Key 不再可用；网页脚本和内容脚本消息均无法读取 Key。

### FR-003 连接测试（P0）

- 保存前或保存后可发起最小翻译请求。
- 首次请求前按 API Origin 申请权限。
- 展示成功模型或明确错误类型。

验收：有效配置可在十秒内得到成功提示；常见 HTTP 错误有不同说明。

### FR-004 网页文本提取（P0）

- 提取标题、段落、列表项、引用、表格单元和图片说明。
- 忽略脚本、样式、代码块、表单、可编辑区域、隐藏内容和已有译文。
- 单块文本长度限制为 2–4000 字符。
- 首次处理触发时已加载的可见内容；本次运行期间增量处理后续新增并变为可见的阅读内容。

验收：普通文章网页中，正文段落覆盖率达到 90%，导航与按钮误译率低于 10%。

### FR-005 批处理与模型调用（P0）

- 为文本块生成稳定 ID。
- 单批默认不超过 4000 字符，具体 token 预算后续按模型优化。
- system prompt 明确网页内容是不可信数据。
- 要求模型返回 JSON，并校验数量、ID 与字段类型。
- `temperature` 默认 0.1。

验收：顺序不同的模型返回仍能按 ID 插回正确段落；格式错误不写入网页。

### FR-006 双语渲染（P0）

- 译文默认显示在对应原文下方。
- 翻译后支持双语、仅原文和仅译文三种显示方式，切换显示方式不得请求模型。
- 用户可在 Options 通过取色盘或十六进制、RGB、RGBA 文本配置译文颜色。
- 每个区块渲染前必须检查偏好色与有效背景的对比度；不利于阅读时优先回退原文字体色。默认提示可让模型在偏好色/原文色两个受限候选中给出建议，但本地 WCAG 对比度门禁拥有最终决定权，模型不得返回任意 CSS。
- Popup 与 Options 使用统一的暖色主题、字段层级、操作状态和响应式间距；主题颜色只作为视觉层，不改变 API Key、网页正文或模型请求的数据边界。
- 使用 DOM `textContent` 渲染，不使用 `innerHTML`。
- 译文具有独立 class，避免重复插入。
- 不删除、覆盖或持久修改网页原文。

验收：模型返回 HTML 或脚本字符串时，页面仅显示文本，不执行代码；三种显示方式可来回切换且不破坏原文，颜色值不能注入额外 CSS；偏好色在相近背景上低于普通文本 4.5:1（大文本 3:1）时，即使模型选择偏好色也必须自动改用通过门槛的原文色或高对比回退色。

### FR-007 翻译控制（P0）

- Popup 展示目标语言、由状态切换的翻译/停止单一按钮和设置入口。
- 未配置模型时，主要按钮引导至设置页。
- 停止操作阻止下一批请求。
- 完成和停止的网页提示自动消失；错误提示保留以便诊断。
- 同一网页的当前译文在页面会话内保留；再次点击翻译会移除旧译文、绕过缓存并重新请求当前模型，界面和文档必须提醒可能产生新费用。
- 浏览器内部页面给出“不支持翻译”的说明。

### FR-008 本地缓存（P1）

- 缓存键包含文本哈希、源语言、目标语言、模型、提示词版本。
- 缓存不包含 API Key。
- 用户可以清理缓存并查看占用空间。
- 默认提供容量或过期淘汰策略。

Alpha 实现说明：缓存保存在可信扩展上下文的独立 IndexedDB 中，默认有效期 30 天、容量上限
50 MiB，超限后按最近最少使用顺序淘汰。缓存键由源文本、语言对、Provider、模型、提示词
版本和实际系统提示词共同生成 SHA-256 摘要；持久化记录只包含摘要、译文、时间和大小，
不包含 API Key、认证头、源文本或网页 URL。全命中不读取 Key、不调用 Provider，也不新增
用量账本；缓存不可用时降级为正常翻译。

验收：相同上下文稳定命中；模型、目标语言或提示词变化后不复用旧译文；部分命中只发送
未命中段落；清空后占用与条目数归零。

### FR-009 动态网页（M1 / P0）

- 使用 MutationObserver 识别后续新增的内容块。
- 对同一节点去重。
- 用户停止翻译后不再处理新增内容。
- Observer 仅在用户主动启动的当前页面运行期间存在，不构成网站级常驻自动翻译。
- 网站级自动翻译必须单独申请对应站点权限。

验收：初次翻译后追加的可见正文无需再次点击即可获得译文；已有节点不重复插入；停止后追加内容不发起翻译请求。

动态可靠性补充验收：虚拟列表将同一候选节点移出后离线改写再插回、节点原地改写、整个 `body` 被替换时，活动会话必须重新读取源文本并继续处理；Observer 只在用户主动启动的会话内观察文档根节点，停止后上述变化均不得产生新译文。

### FR-010 Provider 扩展（P1）

- Provider 通过统一接口实现 `translate` 与 `testConnection`。
- 后续增加原生 Gemini、Anthropic 与本地模型适配器。
- Provider 的认证头、请求体与响应解析不得进入内容脚本。

### FR-011 成本预估与每日预算（M1 / P0）

- 每个模型价格配置包含币种、每百万输入 token 单价、每百万输出 token 单价和价格更新时间。
- 账单视图只展示输入、输出和合计 token，不展示由插件计算的账单金额。
- Options 按用户本地日期展示最近 60 天输入/输出 token 折线图，按 Provider 下的模型分别提供可切换每日序列和汇总，空缺日期补 0；Y 轴根据当前数据量级统一选择 token、K、M 或 B 单位。
- 本地账本按滚动 60 个本地日期保留；读取历史和成功记账时清理更早记录。
- 历史数据只包含通过 TextDuet 发起并成功写入本地账本的请求，必须明确标注为本地记录。
- 仅在官方结构化 API 能精确匹配当前模型并返回合法输入/输出单价时展示价格；查不到、权限不足、格式异常或模型不匹配时不展示数字价格。
- 翻译前根据待发送文本、系统提示词和请求结构估算输入 token。
- 输出 token 以可配置的译文倍率估算，默认提供区间而不是伪精确数值。
- 模型返回 `usage.prompt_tokens`、`usage.completion_tokens` 或兼容字段时写入实际用量；没有返回 usage 时不把本地估算写入 token 历史。
- 每日账本按用户本地时区、Provider 与模型聚合，只记录 Provider 返回的实际输入和输出 token。
- 使用 DeepSeek 官方 API 配置时，用户可以主动查询当前余额；余额只在 Options 当次展示，不持久化、不换算 token。
- 默认阈值为 50%、80%、100%；预算本身默认关闭。
- 预算只在本地执行，不依赖项目服务器，也不承诺替代模型厂商的账单或硬限额。
- 用户可以清空本地用量记录，API Key 不进入账本。

Alpha 实现说明：token 估算使用确定性的本地启发式算法，中日韩字符按一字符约一
token、其他字符按约四字符一 token 计算，并计入系统提示词、请求 JSON 和固定消息开销；
输出区间采用源文本 token 的 0.8–1.4 倍。缺少 Provider usage 时保留本次预估提示但不写入
token 历史，所有金额始终标记为预估并以厂商账单为准。当前 Alpha 支持用户为预算提醒手动填写当前模型价格；
账单界面不展示计算金额。OpenRouter 使用公开官方模型列表接口查询当前模型价格且不会自动
写入手动配置；其他已支持 Provider 没有适用于普通推理 Key 的可靠结构化价格接口时不展示价格。

验收：给定固定价格和 token 用量，预估与结算公式可重复验证；缺失 usage 的响应不写入账本；跨本地日期后自动进入新的每日账本；达到阈值只触发一次对应提醒；最近 60 天曲线按模型拆分、补齐空日期并按数据量级切换 Y 轴单位，且更早记录被清理；账单界面不出现插件计算金额；DeepSeek 余额查询只访问官方端点且不向 UI 返回 API Key。

## 9. 非功能需求

### 性能

- 插件点击前不向普通网页注入常驻内容脚本。
- 单次提取在 2000 个候选元素内目标耗时低于 100ms。
- 同时进行的模型请求默认不超过 2 个。
- Service Worker 可随时终止，流程状态不能只依赖全局变量。

### 兼容性

- 首发唯一目标：当前稳定版 Chrome。
- Node.js 开发环境最低版本为 22。
- M0、M1 和首个公开版本不安排 Edge、Firefox、Safari 的专项测试与发布工作。

### 可访问性

- 所有表单控件有可见或屏幕阅读器标签。
- 键盘焦点清晰，正文与控件符合 WCAG AA 对比度。
- 动画遵守 `prefers-reduced-motion`。
- 不以颜色作为唯一状态信号。

### 可维护性

- TypeScript strict 模式。
- 核心解析、分批、Provider URL 处理必须有单元测试。
- PR 合并前通过 typecheck、test 与 build。

## 10. 隐私与安全要求

### 信任边界

- 网页：不可信。
- 内容脚本：低权限执行层，不持有密钥和 Provider 配置。
- Service Worker：可信执行层，负责密钥与网络访问。
- 模型服务商：用户选择的第三方数据处理方。
- 模型返回值：不可信。

### 必须遵守

1. Service Worker 不接受内容脚本提供的任意请求 URL；URL 只从可信设置读取。
2. 翻译消息必须校验来自浏览器标签页。
3. 所有 API 调用使用 HTTPS。
4. 不使用远程托管的可执行代码。
5. 不收集浏览历史、页面文本、密钥或完整错误响应。
6. MVP 不启用遥测；未来若引入，必须默认关闭并经过独立设计评审。
7. 隐私政策明确：哪些网页文本会在何时发送给哪个服务商。

## 11. 产品指标

MVP 不上传遥测。开发与可用性测试阶段采用人工记录：

- 首次配置成功率。
- 从打开设置到连接成功的中位时间。
- 普通文章的正文覆盖率与误译区域比例。
- 完整网页翻译成功率。
- 每千段返回格式错误率。
- 用户能否根据错误文案独立修复配置。

正式发布前如需产品分析，只能设计本地统计或明确自愿加入的匿名遥测方案。

## 12. V1.0 本地安装版验收

首版只交付可在 Chrome 开发者模式中本地加载的扩展包，不提交 Chrome Web Store 或其他商店。候选版本必须同时满足：

- OpenAI、DeepSeek 和至少一个自定义兼容端点通过真实连接测试。
- 10 个不同结构的文章网页完成双语翻译。
- API Key 未出现在内容脚本、控制台日志、构建产物常量或错误对象中。
- 安装时没有“读取所有网站”权限警告。
- 模型 API Origin 只在用户测试或保存配置时申请。
- 401、404、429、5xx、网络断开和无效 JSON 均有可理解反馈。
- 类型检查、单元测试、生产构建和浏览器手工冒烟测试通过。
- ZIP 解压后可通过 `chrome://extensions` 的“加载已解压的扩展程序”安装，版本、图标、Popup 与 Options 正常显示。
- README、隐私政策、Chrome 权限说明和本地安装指引齐备。

## 14. 已知风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| BYOK 配置门槛 | 普通用户在首次使用时流失 | 服务商预设、连接测试、针对性错误说明 |
| 不同兼容接口存在细节差异 | 相同配置在部分厂商失败 | Provider 适配层、兼容测试矩阵 |
| 网页结构差异巨大 | 漏译、误译或布局变化 | 保守提取、网站规则、可恢复原文 |
| 模型不遵守 JSON 格式 | 批次无法渲染 | 严格校验、有限重试、后续增加结构化输出 |
| API 调用成本失控 | 用户产生意外账单 | M1 成本预估、本地每日预算、缓存与停止按钮 |
| 本地持久密钥被读取 | 用户凭证泄露 | 会话存储为默认、可信上下文限制、清晰风险提示 |
| 官方模型价格过期或不可查询 | 用户误判模型费用 | 只展示结构化 API 的精确模型匹配结果、标注查询日期；查不到就不展示，预算仍以用户配置和厂商账单为准 |
