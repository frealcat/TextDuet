# TextDuet 页面开发标准

> 适用范围：Popup、Options 及扩展页面内所有 React/CSS UI。
> 规范版本：1.0.0，生效日期：2026-08-19。

## 目标

TextDuet 是阅读工具，不是营销页面。所有界面必须优先保证配置、翻译、停止、语言切换和状态查看的可发现性、对齐和键盘可用性。页面不允许依赖截图中的偶然位置或浏览器默认样式。

## 布局契约

- Popup 使用固定工具栏宽度，内容区宽度为 `100%`，任何控件不得造成横向滚动。
- Options 使用单一内容容器：桌面最大宽度 `860px`，窄屏左右内边距不小于 `12px`。
- 每个功能模块必须有明确的根 class；子元素只能使用该模块的后代选择器，不得使用 `.module span` 这类会污染嵌套组件的宽泛规则。
- 语言方向始终使用三列网格：`minmax(0,1fr) auto minmax(0,1fr)`。箭头只占中间列，语言菜单只占左右列。
- Options 的语言方向、显示方式、颜色和快捷开关必须分别占据清晰的行或显式网格区域；不得让 `details`、`label` 或帮助文本依靠隐式网格自动定位。
- 所有表单控件使用稳定的 `min-height`、`min-width: 0` 和 `box-sizing: border-box`，文本过长时换行或截断，不撑破父容器。
- 卡片只用于独立功能模块；禁止卡片嵌套卡片。新增卡片圆角默认不超过 `8px`，已有主题卡片除外。

## 组件契约

- 共享交互必须抽成 React 组件，Popup 与 Options 使用同一状态模型和文案；页面差异只通过 `compact` 等明确属性表达。
- 原生 `select` 或自定义菜单必须有可访问名称、当前值、展开状态和 Escape/外部点击关闭行为。
- 图标按钮必须有 `aria-label` 和 tooltip；文字按钮必须明确动作。
- 异步按钮必须覆盖 idle、busy、success、error、disabled 状态；状态消息不能只使用颜色表达。
- 颜色、间距、圆角、阴影和 z-index 只能使用页面根级 token 或组件 token，不得重复散落魔法值。

## 视觉基线

- 页面背景 `#f5f2ec`，表面 `#ffffff`，正文 `#232018`，主色 `#9c5e2e`，悬停 `#7d4b24`，辅助文字 `#6b6356`。
- 正常文本对比度至少 4.5:1；焦点环必须可见；不使用渐变、光球、霓虹和大面积装饰。
- Popup 标题、控制卡、主操作、显示模式、用量摘要和设置入口按固定垂直节奏排列；Options 标题、卡片标题、字段标签、控件和帮助文本按固定间距排列。
- 文字字号不随视口缩放；英文模型名、URL 和错误信息允许换行。

## 响应式与验收

- 必须检查 Popup 桌面宽度、Popup 窄宽度、Options 桌面宽度和 Options `<=640px` 窄屏。
- 必须检查语言菜单打开、长语言名称、模型名、颜色面板、错误和禁用状态。
- 必须检查 Tab 顺序、Enter/Space 打开控件、Escape 关闭菜单、焦点环和无横向滚动。
- UI 改动完成前运行 `npm run typecheck`、`npm test`、`npm run build` 和 `git diff --check`；生产构建页面还需要截图或等价 DOM 几何检查。
- Agent 只报告自动化和生产构建证据；Chrome 安装态视觉验收由项目所有者完成。

## 禁止项

- 禁止使用全局 `.language-pair span`、`.card label span` 等宽泛选择器覆盖共享组件内部元素。
- 禁止通过负 margin、绝对定位或固定像素补丁掩盖网格错位。绝对定位只用于弹出层、tooltip 和选区快捷入口，并必须有边界处理。
- 禁止把多个功能模块塞进一个隐式网格，使模块顺序依赖 DOM 偶然排列。
