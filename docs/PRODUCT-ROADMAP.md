本文档是 TextDuet 产品范围、优先级、里程碑状态和阶段退出条件的唯一事实来源。它回答“接下来为什么做、先做什么、做到什么程度才进入下一阶段”。具体需求与验收规则仍以 [PRD](./PRD.zh-CN.md) 为准，实际完成记录见 [迭代记录](./ITERATION-LOG.md)，面向用户的版本变化见 [CHANGELOG](../CHANGELOG.md)。

## 1. 文档职责

| 文档 | 负责回答 | 不负责 |
| --- | --- | --- |
| PRD | 产品为何存在、用户是谁、功能和验收要求是什么 | 逐轮进度和发布日期 |
| 本路线图 | 阶段顺序、优先级、状态和退出条件 | 实现细节和逐项工程日志 |
| 迭代记录 | 每轮实际交付、决策、验证证据和遗留问题 | 未来承诺和对外发布说明 |
| CHANGELOG | 某个发布版本给用户带来的变化 | 内部过程、未验证工作和详细测试日志 |
| 架构文档 | 系统边界、数据流和技术决策 | 产品优先级和市场承诺 |

## 2. 路线图原则

1. **先闭环，再扩面**：先稳定“配置 → 预估 → 翻译 → 双语渲染 → 用量记录”，再增加新 Provider 和高级形态。
2. **安全与成本是发布门槛**：API Key 边界、最小权限、纯文本渲染和费用透明不得以赶进度为由延后。
3. **以退出条件驱动阶段**：完成代码不等于完成里程碑；测试、真实 Chrome 验收和文档必须同时满足。
4. **没有日期就不伪造承诺**：未经过项目所有者确认的时间只记录先后关系，不写成发布日期。
5. **范围变更留痕**：新增、移除、延期或改变优先级时，必须记录原因、影响和决策日期。

## 3. 状态定义

| 状态 | 含义 |
| --- | --- |
| 候选 | 有价值，但尚未确认进入范围 |
| 已规划 | 已确认目标、边界和验收条件，尚未开始实现 |
| 进行中 | 已开始实施，但退出条件尚未全部满足 |
| 已验证 | 退出条件已满足，但尚未进入正式发布版本 |
| 已发布 | 已进入带版本号的公开发布物 |
| 已延期 | 仍保留价值，但明确移出当前阶段 |
| 已取消 | 不再计划实施，并记录取消原因 |

只有“已发布”可以表示用户已经能从正式发布渠道获得功能。“已验证”不得替代发布状态。

## 6. M1：可用网页翻译 Alpha

目标：让用户使用自己的 OpenAI 兼容 API，在普通文章页面上安全完成逐段双语翻译，并能预估和记录模型成本。

### M1.1 翻译主链路

状态：**已验证，未发布**。

- Provider 配置、API Origin 按需授权与连接测试。
- 阿里云百炼 Qwen 显式预设，底层复用已验证的 OpenAI 兼容协议。
- 可见阅读文本提取、嵌套去重、4000 字符分批。
- 用户启动后监听当前页面新增的已加载正文，增量去重翻译并在停止时断开。
- 超时、有限重试、按标签页取消和逐批进度。
- 严格校验模型 JSON、段落 ID 与数量，译文使用纯文本插入。

### M1.2 成本与每日预算

状态：**已验证，未发布**。

- 翻译前 token 和费用区间预估。
- 只将 Provider 响应返回的实际 usage 写入 IndexedDB 本地每日账本；缺失时不混入估算值。
- 最近 60 天输入/输出 token 折线图、按模型切换的每日序列与汇总、滚动清理和动态 Y 轴单位。
- 账单只展示 token；OpenRouter 官方结构化价格可用时按精确模型展示，其他 Provider 查不到则隐藏。
- DeepSeek 官方配置支持用户主动查询余额，结果不持久化、不换算 token。
- 50%、80%、100% 每日阈值提醒。
- 当前模型手动单价配置和本地记录清理。

### M1.3 本地翻译缓存

状态：**已验证，未发布**。

- 缓存键包含文本哈希、源语言、目标语言、模型和提示词版本。
- 明确容量、过期和淘汰策略。
- 缓存不含 API Key；用户可查看占用并清理。
- 缓存命中不得重复计入模型用量。

当前进度：实现、单元测试、生产构建、Mock runtime 界面验收和真实 Chrome 已安装扩展的 IndexedDB 冒烟测试均已完成。生产 MV3 构建在 Chrome for Testing 147 中完成缓存写入、重载全命中、零 Provider 请求和清理归零验证。

### M1.4 合成语料与重点网站验收

状态：**已验证，未发布**。

- 建立原创合成 HTML 语料和确定性 Mock Provider 回归。
- 完成 P0 网站公开页面的 Chrome 验收矩阵。
- 记录正文召回、误译、段落对应、重复运行和停止行为。
- 建立提取性能基线。

当前进度：Chrome 安装态回归已覆盖 6 个原创 HTML 语料、虚拟列表节点复用、原地改写、body 替换、停止行为、Service Worker 回收和恶意模型文本纯文本渲染。TD-2026-010 将默认 P0 矩阵收敛为 16 个已验证可访问 URL，优先覆盖海外社区、框架技术文档和创意设计内容；候选阶段受限或网络失败页面不计入默认目标。

### M1.5 Alpha 收口

状态：**已验证，未发布**。

- 完善连接与翻译错误分类的浏览器验证。
- 完成官方价格参考入口的来源、核对日期和适用规则；数字价格在缺少可靠维护机制时保持手动填写。
- 补齐隐私政策初稿、权限说明和开发者安装指引。
- 完成真实 Chrome 扩展链路和代表性 Provider 人工验收；真实 Key 不进入仓库和日志。

当前进度：代表性阿里云 Qwen Provider 的最小连接、GitHub README 和 Chroma 长文章真实调用链路已通过，实际 usage token 已进入本地账本。官方 API 能力已按普通推理 Key、管理凭证、余额和结构化价格能力分级；账单改为 60 日本地实际 token 曲线，OpenRouter 可自动查询当前模型价格，DeepSeek 可按用户操作查询余额。TD-2026-013 已完成干净依赖构建、生产 Manifest/ZIP 安全门禁和独立 Chrome 配置安装态验收；项目所有者已在本机 Chrome 使用 Qwen 确认首版可正常使用。首版交付范围已收敛为本地加载，不以商店资料或公开联系渠道作为阻塞项。

M1 退出条件：

- M1.1–M1.5 均达到“已验证”。
- [网站兼容与验收计划](./SITE-COMPATIBILITY.md) 的 Alpha 阻塞项通过。
- TypeScript、单元测试、生产构建、Manifest 检查和 Chrome 手工冒烟测试通过。
- 没有未处理的 API Key、权限、模型输出注入或费用误导 P0 风险。

退出结论：上述条件已在 TD-2026-013 满足。M1 状态为已验证、未发布；项目所有者已在 TD-2026-017 单独授权创建开发检查点 commit，但 tag、push、GitHub Release 和对外分发仍需另行授权。

## 7. M2：本地 Beta

状态：**已验证，未发布**。

- 增强虚拟列表节点复用、复杂可见性变化和网站规则适配。
- 建立可维护的网站规则层，不用大量站点硬编码污染核心提取器。
- 提供译文显示样式和基础阅读偏好。
- 提供默认本地生成、用户预览后主动提交的兼容性诊断包。
- 建立 Chrome + Playwright 的公开页面自动回归。
- 完善面向本地安装用户的已知问题、诊断导出和反馈入口。

当前进度：TD-2026-014 至 TD-2026-018 已验证。TD-2026-019 已实现无网页状态浮层、语言对、SSE 首段增量、动态后续批次、统一选区样式、首批小批次加速、选区边角快捷图标和共享语言弹出组件。TD-2026-020 正在处理已完成批次回显、header/navigation/footer 可读文本召回和选区快捷入口稳定性；已修复快捷图标监听被空选区清理、普通正文容器无法识别以及默认开关开启的问题，等待项目所有者复验。V1.0 发布候选仍不启动。诊断默认不上传、不包含正文、Key、查询参数、片段或截图。

M2 退出条件：

- 虚拟列表节点复用、复杂动态内容和 Service Worker 恢复行为通过浏览器测试。
- 兼容性报告默认不上传，不包含正文、Key、表单内容或私人 URL。
- 本地 Beta 已知问题、反馈入口和回退方式清晰。

## 8. V1.0：本地安装版

V1.0 必须满足：

- [PRD 第 12 节](./PRD.zh-CN.md#12-v10-本地安装版验收)全部通过。

- P0 重点网站达到发布阻塞标准。

- 没有未关闭的 P0 安全、数据丢失、费用误导或网页破坏问题。

- 最终 ZIP 可解压并从 `chrome://extensions` 本地加载；不以 Chrome Web Store 上架为退出条件。

## 9. V1.x 与 V2 候选池

以下项目只有在进入“已规划”后才算正式范围：

- 原生 Gemini、Anthropic 和本地模型 Provider。
- 网站级自动翻译及其独立 Origin 授权与撤销入口。
- 术语表、译文风格、快捷键和更丰富的阅读样式。
- 划词、悬停、输入框翻译。
- PDF、字幕、图片 OCR；每种载体分别立项，不绑定打包交付。
- Edge、Firefox、Safari 兼容。
- Chrome Web Store、其他商店或自动更新分发；当前不规划，未来如需支持必须独立立项。

## 10. 路线图维护规则

1. 路线图只记录产品级交付物，不把每个代码任务写成里程碑。
2. 状态变更必须在同一轮更新 [迭代记录](./ITERATION-LOG.md)，附验证证据或延期原因。
3. 新增范围必须说明用户价值、所属阶段、依赖、风险和退出条件。
4. 移出当前阶段时使用“已延期”并记录去向，不静默删除。
5. 正式发布日期、发布渠道和版本号由项目所有者确认；Agent 不得自行承诺或发布。
6. 每次发布后复核路线图，关闭已发布项，并从候选池选择下一阶段，而不是自动扩大范围。
